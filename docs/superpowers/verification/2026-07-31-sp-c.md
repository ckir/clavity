## Divergence from the operator's personal copy

Both scripts were read in full (not grepped) and their `case "$skill" in` blocks compared directly.

**Shipped hook** (`clavity-dotnet/plugin/hooks/agy-seam-inject.sh:38-42`, byte-identical in `clavity-classic`) —
2 seam patterns, each a case arm that sets `discipline`:

```

*brainstorm*)                     discipline="agy-first" ;;
```

**Personal hook** (`~/.claude/hooks/agy-seam-inject.sh:19-32`) — 6 case arms covering 7 glob patterns (the last
arm ORs two patterns together):

```
*brainstorm*)                                              SEAM=design-fork
*writing-plans*)                                            SEAM=plan-review
*requesting-code-review*)                                   SEAM=execution-verification
*systematic-debugging*)                                     SEAM=recovery
*finishing-a-development-branch*)                            SEAM=merge-gate
*subagent-driven-development*|*executing-plans*)             SEAM=implementation-capstone (labelled AGY-CAPSTONE)
```

**Diff of the two seam-pattern sets:**

- Shared (bound in both): `brainstorm`, `finishing-a-development-branch`.
- In the personal hook only (5 patterns): `writing-plans`, `requesting-code-review`, `systematic-debugging`,
  `subagent-driven-development`, `executing-plans`.
- In the shipped hook only: none — every shipped seam pattern is also present in the personal hook.

**(a) Does the personal hook fire on seams the shipped hook does not?** Yes — confirmed above: 5 patterns
(`writing-plans`, `requesting-code-review`, `systematic-debugging`, `subagent-driven-development`,
`executing-plans`) exist only in the personal copy.

**(b) Does the shipped hook narrow the capstone trigger to `finishing-a-development-branch` specifically?**
Yes. The shipped hook binds the `agy-capstone` discipline to exactly one pattern, `*finishing-a-development-branch*`
(Step 3). The personal hook binds AGY-CAPSTONE-style behavior more broadly: `*finishing-a-development-branch*`
(SEAM=merge-gate) **and** `*subagent-driven-development*|*executing-plans*` (SEAM=implementation-capstone, whose
payload text explicitly opens with "AGY-CAPSTONE — this skill EXECUTES a plan..."). So the personal copy fires
capstone-flavored injections on 3 patterns; the shipped hook fires the equivalent on 1. Narrowing confirmed.

**(c) Does the personal hook literally reference `brainstorming` and `subagent-driven-development`?** Checked
literally against the file text, not assumed:
- `subagent-driven-development` — present verbatim, line 30 (`*subagent-driven-development*|*executing-plans*`).
  This pattern is genuinely personal-hook-only — it is one of the 5 extra seams in (a).

  so the observation "it fired on brainstorming" is accurate as a factual claim about the personal hook. **But**
  it is NOT one of the personal hook's "additional" seams relative to the shipped hook: the shipped hook also
  matches `*brainstorm*` (mapped to `agy-first`, Step 3's sibling arm). So using `brainstorming` as an example of
  a seam "which the shipped hook deliberately does not carry" is incorrect — that seam is carried by both. Only
  `subagent-driven-development` supports the claim as stated; `brainstorming` does not.

hook does not carry — but the verified list of those extra seams is `writing-plans`, `requesting-code-review`,

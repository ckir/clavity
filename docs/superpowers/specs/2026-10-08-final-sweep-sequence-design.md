## The branches (order: T, C, G, H, RR, R; X only if the owner rules BUILD; then one release)
Each branch runs the earlier sweep's cycle unchanged: **(a)** re-measure each item at the branch's own start - an item that no longer reproduces is PROPOSED for kill to the owner with the measurement quoted, the driver never closes an item itself; **(b)** a line-level plan written then, against the code as it is then, read-verified (the repo's plan-vs-spec rule); a plan is dry-run in a throwaway worktree by a fresh executor before panel review (measured on Branch 4: it found a regression, a compile error and a wrong record member that five agy rounds missed); **(c)** implement with a failing control first and a mutant for every new test; **(d)** AGY-CAPSTONE until a clean round, with a reading probe (the peer's first-round green has been wrong before) and an envelope check - `git status` including UNTRACKED files, HEAD, reflog, repo-root listing - after EVERY agy round; **(e)** AGY-TEST-AUDIT; **(f)** merge `--no-ff` to local `main`; the owner owns every push. A source change made at (e) sends the branch back to (d) for a delta round.

## The release
After R is merged and the owner has pushed `main`: the OWNER runs `! just release`; the driver then verifies `git ls-remote origin refs/heads/release` equals the tag commit, asks the owner to `/plugin marketplace update clavity` and checks `/plugin`, and flips the ROADMAP statuses from IMPLEMENTED to SHIPPED. If the release run fails (the one step this design cannot rehearse), the fix goes forward as a new commit on `main` and the release is re-run; §63 is the most likely cause and the plan for R says so.

## Rules for the whole sequence
- **Nothing is parked.** An anomaly found during a branch is fixed in that branch or ruled closed; it is not promoted to a new open section unless the owner rules that it must be, in which case the "nothing open" claim is amended in the same message.
- **Both recommendations to the owner on every fork, the owner decides** (AGY-FIRST); agy unreachable means stop and ask, never self-exempt.
- **Every agy payload ends with the ask-don't-guess line.** `agy_ask` takes `message` (not `payload`); name an out-of-repo build path in any brief that could tempt a build, or forbid building.
- **Never two Pester suites or two test hosts at once;** read counts, not exit codes. Timing figures are measured at the top level only.
- **A plugin change** mirrors to `clavity-classic` in the same commit wherever a twin exists (the pair the repo pins byte-identical); installs come from the `release` branch and the release workflow bumps the version, so there is no manual bump and no mid-sweep reinstall halt (the old "merge, push, reinstall, check the version" halt proves nothing since Branch 17).

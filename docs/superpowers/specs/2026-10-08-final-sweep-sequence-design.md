## The tracker format - decided 2026-10-08 (AGY-FIRST + negotiation, owner adopted)
Consult: seam `.clavity/seams/branch-t-format-agy-first.md`, replies `.clavity/scratch/branch-t-format/reply.md`, `reply-2.md`, `reply-3.md` (envelope intact on all three asks). Every point below is agreed by agy and the driver and adopted by the owner:
1. **Where the status lives:** the heading is the TITLE ONLY; the next non-blank line is `**Status:** <TOKEN> <YYYY-MM-DD> - <one line>`; history moves into the body, verbatim.
2. **Vocabulary (one closed set for all trackers):** open partition `OPEN`, `SCHEDULED`, `IMPLEMENTED` (built on an unmerged branch); closed partition `SHIPPED` (merged to `main`), `CLOSED-BY-RULING` (an accepted limitation with a reopen condition), `KILLED` (will not be done). Release is NOT a token: a separate `**Released:** clavity-vNN` line is added once when a release ships. (Agy first proposed collapsing IMPLEMENTED into SHIPPED and CLOSED-BY-RULING into KILLED; it withdrew both after one counter-turn showing the repo's own usage - IMPLEMENTED means "merge pending", and nine headers carry "NOT released".)
3. **No open item may hide inside another:** an open sub-item (`§29b`, `§65` Fork 2) becomes its own `§N`, titled "... (formerly §29b)"; closed lettered history stays as body prose.
4. **Migration:** every entry of all three trackers (`clavity-dotnet/ROADMAP.md`, `docs/backlog/*.md`, `agy-autotrain/docs/fix-the-tool-backlog/*.md`; plus `review-relay/ROADMAP.md`) is normalised once, history kept verbatim; an entry needing a judgement call is flagged to the owner, never guessed.
5. **The gate** (in or beside `scripts/check-roadmap-claims.ps1`): REFUSES an entry whose next non-blank line is not a valid status line or whose token is outside the set; REQUIRES evidence for a closed token - `SHIPPED` cites a commit sha (verified by the existing Check B), `CLOSED-BY-RULING` has a matching entry under "Non-goals / accepted limitations", `KILLED` states a reason; LISTS every open-partition item (the end-of-sweep check runs this). It covers the fix-the-tool frontmatter too, which voids coverage-debt boundary H.
6. **Where an agent learns it:** one canonical format file, plus a short inline excerpt (the status-line shape and the token list, about three lines) in the promote step of `open-issues`, `agy-capstone` and `agy-test-audit` in both plugins, kept identical to the canonical file by a parity check in the style of `scripts/check-seed-artifacts-synced.sh`.
7. **Considered and not chosen:** a structured YAML/JSON source generating the markdown (agy's alternative) - markdown stays the source; a strict status line plus the gate removes the parsing ambiguity without re-architecting three hand-edited trackers before the release.
Open point for the plan (agy did not answer it): how an item closed by a docs-only commit cites its evidence (the docs commit's sha is still a sha; the plan states the rule).

## The release
After R is merged and the owner has pushed `main`: the OWNER runs `! just release`; the driver then verifies `git ls-remote origin refs/heads/release` equals the tag commit, asks the owner to `/plugin marketplace update clavity` and checks `/plugin`, and flips the ROADMAP statuses from IMPLEMENTED to SHIPPED. If the release run fails (the one step this design cannot rehearse), the fix goes forward as a new commit on `main` and the release is re-run; §63 is the most likely cause and the plan for R says so.

## Rules for the whole sequence
- **Nothing is parked.** An anomaly found during a branch is fixed in that branch or ruled closed; it is not promoted to a new open section unless the owner rules that it must be, in which case the "nothing open" claim is amended in the same message.
- **Both recommendations to the owner on every fork, the owner decides** (AGY-FIRST); agy unreachable means stop and ask, never self-exempt.
- **Every agy payload ends with the ask-don't-guess line.** `agy_ask` takes `message` (not `payload`); name an out-of-repo build path in any brief that could tempt a build, or forbid building.
- **Never two Pester suites or two test hosts at once;** read counts, not exit codes. Timing figures are measured at the top level only.
- **A plugin change** mirrors to `clavity-classic` in the same commit wherever a twin exists (the pair the repo pins byte-identical); installs come from the `release` branch and the release workflow bumps the version, so there is no manual bump and no mid-sweep reinstall halt (the old "merge, push, reinstall, check the version" halt proves nothing since Branch 17).
